# 07 表关系与索引规范

## 1. 主键

所有业务表：

```text
id BIGINT
```

由 Snowflake 生成。

## 2. 时间

全部：

```text
TIMESTAMPTZ
```

数据库以 UTC 写入。

## 3. BIGINT API

JSON 中 ID 必须序列化为字符串：

```json
{
  "id": "123456789012345678"
}
```

## 4. 高频索引

必须覆盖：

- user_id + created_at
- status
- code
- unique business key
- foreign key
- tool_id + date
- article_id + created_at
- trace_id

## 5. 唯一索引

推荐：

```text
biz_user.username
biz_user_login_identity(type, normalized_value)
biz_user_level.code
biz_growth_rule.code
biz_point_rule.code
biz_growth_event.event_id
biz_growth_event.idempotency_key
tool.code
blog_article.slug
blog_like(user_id, article_id)
blog_favorite(user_id, article_id)
```

## 6. 账务流水

积分/成长值流水只允许：

```text
INSERT
SELECT
```

不允许业务 UPDATE/DELETE。

## 7. 外键

核心关系建议使用数据库 FK。

对于高写入日志、跨域历史数据，可根据分区/归档策略决定是否保留物理 FK，但必须在最终迁移规范中明确。

## 8. JSONB

JSONB 只用于：

- 配置
- metadata
- 可扩展规则参数
- 非核心查询字段

不要把核心关系全部塞进 JSONB。
