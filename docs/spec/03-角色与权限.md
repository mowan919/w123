# 03 角色与权限

## 1. 权限链

```text
User
 ↓
Role
 ↓
Role Inheritance
 ↓
Page
 ↓
Menu
 ↓
Button
 ↓
API
 ↓
Field
 ↓
Data Scope
```

## 2. Role

Role 至少包含：

- id
- role_code
- role_name
- status
- description
- created_at
- updated_at
- deleted_at

## 3. 多角色

用户支持多个角色。

有效权限：

```text
Union(all assigned role permissions)
```

## 4. Role Inheritance

V1 支持角色继承。

继承权限必须参与 Effective Permission 计算。

必须避免：

- 循环继承
- 无限递归
- 重复权限
- 删除父角色导致隐式错误

## 5. Page

Page 表示用户可以进入/查看的页面。

页面必须可以由后台管理平台配置。

## 6. Menu

Menu 表示导航结构。

一个 Menu 可以关联多个 Page。

## 7. Button

控制页面内操作入口。

例如：

- create
- edit
- delete
- export
- reset_password

## 8. API

API Permission 是后端强制授权。

不能只依赖前端按钮隐藏。

## 9. Field

字段权限：

- VISIBLE
- HIDDEN
- READ_ONLY
- EDITABLE

最终字段策略需要由后端统一计算并向前端输出。

## 10. Data Scope

支持：

- ALL
- DEPARTMENT
- DEPARTMENT_CHILDREN
- SELF
- CUSTOM

部门管理员默认：

```text
DEPARTMENT_CHILDREN
```

## 11. Permission Preview

建议提供权限预览能力：

- 用户当前有效权限
- 来源角色
- 继承链
- Data Scope
- Field 权限

## 12. Permission Version

权限修改必须立即生效。

实现可以采用权限版本号 + Redis 缓存失效，但具体 Redis Key 格式可在技术设计阶段确定。
