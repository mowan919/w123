# VCTN 后台管理平台 V1.0 — 需求冻结确认表

> 本文件是业务规则冻结基线。Agent 不得擅自修改其中的冻结结论。

## 1. 冻结决策

| 编号 | 决策项 | 冻结结果 |
|---|---|---|
| 1 | 部门管理员数据范围 | 本部门 + 所有子/下属部门 |
| 2 | 用户角色数量 | 支持多个角色，权限取并集 |
| 3 | 角色继承 | V1 支持 |
| 4 | Page/Menu 关系 | 一个 Menu 可关联多个 Page |
| 5 | 权限变更 | 立即生效 |
| 6 | 踢下线 | 支持单 Session 与全部 Session |
| 7 | SUPER_ADMIN 是否可被其他管理员踢下线 | 不允许；仅本人可 logout |
| 8 | 用户删除 | 禁用 + 逻辑删除 |
| 9 | 密码策略 | 见下文 |
| 10 | MFA | 按角色 + 按用户；用户级优先；V1 Provider 尚未冻结 |
| 11 | 日志保留 | Access 30d / Security 180d / Operation 180d / Audit 2y / Application 30d |
| 12 | 日志脱敏 | phone/email/token/password/MFA Secret 按规则处理 |

## 2. 密码策略

- 最少 12 个字符
- 必须包含大写字母、小写字母、数字、特殊字符
- 最近 5 个密码不可重复
- 90 天必须更换
- 连续 5 次失败锁定 30 分钟
- 管理员重置密码后，首次登录必须修改密码

## 3. 权限模型

```text
User
 ↓
Role
 ↓
Role Inheritance
 ↓
Page Permission
 ↓
Menu Permission
 ↓
Button Permission
 ↓
API Permission
 ↓
Field Permission
 ↓
Data Scope
```

- Page：是否可进入/查看页面
- Menu：导航可见性
- Button：操作入口可见性
- API：后端接口授权
- Field：VISIBLE / HIDDEN / READ_ONLY / EDITABLE
- Data Scope：ALL / DEPARTMENT / DEPARTMENT_CHILDREN / SELF / CUSTOM

前端权限不能代替后端 API 权限。

## 4. MFA

支持扩展 Provider 架构，例如 TOTP、Email、SMS、WebAuthn/Passkey 等，但 **V1 的具体 Provider 尚未冻结**，不得由 Agent 擅自确定为最终需求。

MFA 策略优先级：

```text
User Policy > Role Policy > System Default
```

## 5. Session

必须支持：

- 在线状态
- Session 列表/详情
- 登录时间
- 最后活跃时间
- IP
- User-Agent / Device
- 过期时间
- revoked_at / reason
- 单 Session revoke
- 全 Session revoke

SUPER_ADMIN 可管理正常用户；其他管理员不能 revoke SUPER_ADMIN。

## 6. ID / 时间 / 删除

- 业务 ID：BIGINT + Snowflake
- API JSON 中 BIGINT ID 统一序列化为字符串
- 不使用自增业务 ID
- 不使用 UUID 作为业务主键
- 时间统一 UTC
- DB snake_case
- 默认逻辑删除，使用 deleted_at
- 唯一约束必须考虑逻辑删除

## 7. 日志

必须区分：

- Access Log
- Security Log
- Operation Log
- Audit Log
- Application Log

Audit Log 为 append-only。

## 8. 敏感信息

- 手机：`138****1234`
- 邮箱：`abc***@example.com`
- Token：只保留前 6 个字符
- Password：绝不记录
- MFA Secret：绝不记录
